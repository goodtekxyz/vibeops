### 결정 요약

- VibeOps는 코드를 생성하지 않는다(Cursor가 생성). VibeOps는 부트스트랩 + TASK 라이프사이클 + Notion 동기화 “레일”이다.
- Source of Truth는 Git의 `docs/tasks/*.md`와 `docs/project/*.md`. Notion은 사람이 보는 대시보드이고 메타만 동기화.
- 모든 변경 명령은 가능한 `--dry-run`을 제공.
- `init`은 idempotent, 기본은 덮어쓰지 않음(`--force` 필요).
- `task rollback`은 안내가 기본, 파괴적 작업은 `--confirm` 필요.

## TASK-001 · CLI bootstrap 완료

VibeOps CLI의 최소 실행 가능한 뼈대를 만들었다. 모든 도메인 명령은 stub만 등록되어 있고 본체 구현은 TASK-002 이후에서 채운다.

### 추가/변경된 파일

- 신규: `package.json`, `tsconfig.json`, `.gitignore`, `pnpm-lock.yaml`
- 신규: `src/version.ts`, `src/cli.ts`

- 신규: `src/commands/agent-list.ts`, `agent-show.ts`, `agent-prompt.ts`

- 갱신: `docs/tasks/TASK-001-cli-bootstrap.md` (Status → done, Result, Test Result)
- 갱신: `docs/project/03-current-state.md`

### 결정 요약

- 패키지: `vibeops@0.1.0`, ESM(`type: module`), Node 20+, `bin.vibeops → dist/cli.js`.
- CLI 프레임워크: **commander v12**. 한 줄짜리 sub-command 등록 + 보일러플레이트 없는 자동 `--help`.
- `--version`은 `src/version.ts`가 런타임에 `package.json`을 직접 읽어 노출(JSON import attribute의 ESM/NodeNext 호환 이슈 회피).
- `task prompt <taskId> --agent <name>`는 별도 파일 없이 `cli.ts`에서 `agent-prompt.ts`를 재사용해 위임. 명령은 16개, 스텁 파일은 15개.
- 스텁 출력 컨벤션: `[vibeops] not implemented yet: <cmd>` + 후속 TASK 참조 경로 한 줄.
- 본 라운드 사용자 스코프에 따라 다음은 보류: `vitest` 스모크(TASK-001 AC#5), `.prettierrc` / `.eslintrc.cjs`. 후속 TASK 또는 별도 보강 TASK에서 추가한다.
